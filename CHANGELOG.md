# Changelog

## Unreleased — application version remains 0.6.0

- PayPamin Flow now starts minimized in the system tray for every start path: OS autostart, manual launch, direct source launch and update restart. Starting the app again still activates and focuses the existing window through the single-instance guard. The tray-unavailable fallback leaves the window visible without a blocking exit prompt, and the behavior can be turned off in Settings (`--minimized` still forces it for autostart).
- Added local, reviewable self-learning. Saved invoices teach customer email, logo, currency and invoice text defaults plus supplier currency and payment terms; confirmed PDF previews teach a supplier's wording layout for later imports. Strong repeated evidence (three consistent observations, or high layout similarity with a clear margin) is applied automatically, weaker evidence (two observations) asks once before use, ties are never applied, and a declined suggestion stays suppressed until more evidence arrives. **Settings → Review learning** lists each value with its evidence and lets the user forget one value or all learning without touching invoices, reminders or templates. Learning is on by default, can be disabled, stays in the local database and is included in ZIP backups. Reminder recipients used for an opened draft are learned per customer; the firm P1/P2 standard texts, deadlines and fees remain fixed because they contain invoice-specific amounts and dates rather than reusable templates.
- Added per-user single-instance ownership on Windows, macOS and Linux. A later start activates and lifts the existing window instead of creating a duplicate, including when it is hidden in the system tray. Activation uses a loopback-only, token-authenticated channel; update restarts hand ownership from the old process to the confirmed new UI.
- Refreshed the PayPamin Flow invoice/P/check icon with a clearer rim and palette, regenerated PNG/ICO/ICNS variants and strengthened native Windows branding on both root and owner window handles for the taskbar, Alt+Tab and Task Manager's app view. Tray, secondary windows, autostart, macOS Dock and Linux use the same product artwork. Task Manager's Details tab can still show pythonw.exe's embedded icon because replacing that requires the native EXE excluded by the Python-only distribution.

- Improved accessibility verification and large-text behavior: real Tk integration tests now run with Xvfb on Linux CI and with a desktop display where available, covering visual focus traversal, 200% forms, focused-widget scrolling and palette changes. Long dialogs are resizable and two-direction scrollable, focused controls are revealed automatically, and email text has a vertical scrollbar. Added a manual NVDA/VoiceOver/Orca checklist; automated widget tests do not claim to verify screen-reader announcements.
- Added automatic system high-contrast support for Windows, macOS and GNOME/GTK desktops. A high-contrast palette now covers ttk controls, classic Tk text/canvas widgets, focus indicators and menus, with live non-blocking updates and a safe normal-palette fallback. Invoice data, PDF content and reminder history remain unchanged.
- Added keyboard and accessibility support: visible high-contrast focus indicators, visual-order Tab/Shift-Tab traversal isolated per dialog, F10/Alt menu access, F1 shortcut help, common invoice shortcuts, Shift+F10 for the invoice context menu, and persistent 80–200% text scaling for menus, controls, tabs, tables and text areas. Settings and JSON backup retain the scale; invoice data, PDF content and reminder history are unchanged.
- Removed Python-runtime updates from application startup and removed automatic weekly add-on upgrades. Existing Python is reused unchanged; a runtime is installed only when no Python exists. Missing dependencies can still be recovered at startup without upgrading existing packages.
- Added the explicit **Help → Update Python add-ons** offer on Windows, macOS and Linux. It asks for confirmation before upgrading requirements in the existing interpreter, never creates a venv or parallel runtime, logs failures and leaves the app usable with its existing packages. The separate PayPamin Flow release update remains unchanged.
- Retained the console-free Windows Python-runtime guard for manual and OS-login starts. It inventories PATH, Python Install Manager and standard install locations before changing anything, blocks installation after a failed inventory, prevents WindowsApps aliases from triggering an implicit install and installs the recommended stable default only when no Python exists. Unmanaged, system and virtual-environment Python remains untouched. Existing autostart shortcuts migrate through normal autostart synchronization.
- Stopped the post-import P1/P2 readiness dialog after automatic duplicate-only, paid-only, cancelled or failed scans where no new invoice was imported. Manual scans retain their separate due-reminder dialog and duplicate summary; automatic duplicate-only batches stay silent as intended.
- Corrected the creator and copyright name to **Rickard Längkvist** throughout application information, source notices, documentation, SVG metadata and all PNG assets. The product name and icon artwork are unchanged.
- Made the Swedish and English P1/P2 email texts firmer: the invoice is stated as overdue, full payment must be received by the fixed final payment date, and P2 explains that the matter may be escalated without any further reminder. The standard email subject and body contain no interest information. Existing reminder fees, historical snapshots, editable previews and manual sending are preserved.

Customer names and guessed SVG filenames are never substituted, and ambiguous logo associations add no guessed suffix.

After unresolved errors are captured, technical log files whose last write is from yesterday or earlier move into the dated archive; today's files remain active. Rotation now happens before the first record on a new day and at 5 MB with unique numeric names instead of deleting older rotations. Existing archives are never overwritten, collisions receive a `legacy-` prefix and symlinks are not followed.

Archiving, rotating or removing a technical source no longer drops an unresolved incident. **Help → Mark error log as resolved** archives the reviewed errors under `logs/arkiv/resolved/YYYY-MM-DD/` after confirmation and records their fingerprints so unchanged sources cannot reintroduce them; a new timestamp is treated as a new incident. Cancellation changes nothing.
- Reusable customer contacts now retain the latest non-empty SVG logo used for the same normalized customer in addition to its email addresses. The next invoice inherits both, including a manually entered new invoice saved without dialog prefill; legacy invoices with no explicit logo can use the customer logo before the global fallback.
