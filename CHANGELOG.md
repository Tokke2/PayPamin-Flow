# Changelog

## Unreleased — application version remains 0.6.0

- Fixed the real cause of the soft, blurry window. Two independent mistakes were stacked on top of each other: the process never declared **Windows DPI awareness**, so Windows drew the window at 96 DPI and bitmap-stretched the finished picture on a 125–200 % display, and the accessibility style applied the text zoom to **both point sizes and pixel metrics** although Tk already scales points from the screen DPI. Points are now scaled once, while pixels (`padding`, row heights, focus rings, tree column widths and window geometry) follow the display factor, and the process declares per-monitor-v2 / per-monitor / system DPI awareness before Tk creates its interpreter. The wordmark and header icon are downsampled once with a good filter from the 1024 px master instead of letting the window manager stretch a small bitmap.
- **Avsluta helt** and **Dölj i systemfältet** are now both visible in the footer next to **Ta bort vald**, so closing the window to the tray is a visible choice rather than something to find in a menu. A full exit asks once and states plainly that the app also leaves the system tray. The footer defaults line is built from the saved settings and the legal amounts instead of a hard-coded sentence, on two rows so the buttons can never clip it.
- Update downloads now **retry** on HTTP 408/425/429/5xx and on timeouts or dropped connections: three attempts with a growing pause. A 504 from GitHub while a release asset is still being generated therefore no longer ends the update with an error. Permanent failures such as HTTP 404, a too-large package or an unsafe URL still stop immediately with the same message as before.
- Background watchers stop cleanly when the window closes. The import scan, the update check and the update installation poll asked a destroyed window for its widgets and logged `invalid command name` / `cannot invoke "toplevel"`; they now check that the window still exists before touching it, a closed window counts as a normal stop and is logged as information, and the invoice list refresh skips a destroyed tree view. The previously reported `UnboundLocalError` in the detail view could not be reproduced in the current code and no code path stores that name.
- **Late-payment interest is now 10 %**, the reference rate 2.00 % plus eight percentage points under 6 § räntelagen, and it is fixed like the fees. The old 23 % was above the ceiling in 19 a § konsumentkreditlagen (referensräntan + 20 points = 22 %) as well as above the statutory default, so a consumer reminder could not have relied on it. The rate is no longer a setting; the field is gone and a stored value is removed at start, while reminders already sent keep the rate they were printed with. `REFERENCE_RATE` in `fee_rules.py` is the one number to update when Riksbanken sets a new reference rate on 1 January or 1 July. The app still prints the clause only — it never calculates an interest amount, and interest is never added to a fee.
- The two amounts are **fixed by law and cannot be changed**: **60 kr** for a private individual (4 §) and **450 kr** for a business or authority (4 a §). The editable fee and compensation fields are gone from Settings together with the “lock the fee” checkbox — the dialogue now only shows `Påminnelseavgift: 60,00 kr · Förseningsersättning: 450,00 kr`, and no code path reads a fee from settings any more. A value left by an older version (typically 150 kr) is removed from the database at start, so it can neither be charged nor keep travelling in journal exports and backups as if it were a valid setting. Historical reminders keep the amount they were sent with.
- Fees now follow **lag (1981:739)** instead of one flat amount. A **private individual** is charged a reminder fee of at most **60 kr** (4 §), a **business** or an authority gets **450 kr late-payment compensation** (4 a §) and then no reminder fee at all, because 5 § 2 st. does not allow both for the same claim. The customer type is stored per invoice; older databases default to *private*, since 60 kr is lawful in every relationship. An amount above the cap now **stops the reminder** with an explanation instead of printing it — 6 § makes a wider term void, so no agreement can raise it. Because the amounts are fixed, the app can no longer produce an amount over the cap by mistake; the guard stays in place against a hand-edited database and reports the problem instead of printing an unlawful claim. The cap is in SEK, so an invoice in another currency is flagged rather than converted at a guessed rate.
- **Fixed a real double charge.** P1 and P2 each added the fee, so two reminders for one invoice came to 300 kr against a legal 60 kr per claim. The fee is now charged **once per claim**: P2 repeats the amount fixed with P1, the PDF shows it once with a history row that carries no fee, and the e-mail text says so instead of listing “P1 and P2” fees. The P1 fee wins even if the setting changes in between, and the P2 snapshot keeps the amount that was actually charged.
- Each reminder now names the paragraph it rests on (`Påminnelseavgift enligt 4 §` or `Förseningsersättning enligt 4 a §`) in the PDF and in the confirmation dialogue, and the selected invoice shows its customer type and basis in the detail line. Where the right to the fee was agreed (agreement at purchase, quote, or only on the invoice) is recorded per invoice; “only on the invoice” is reported as usually too late, because the debt arose before the invoice was written. The customer type, the agreement and the fee kind travel into the P1/P2 snapshots, the reminder journal and ZIP backups.

- A release now attaches **exactly two files**: `PayPamin-Flow-Python.zip` and `PayPamin-Flow-Python.zip.sha256`. The per-file build manifest is no longer published — it stays a local build record from `packaging/package_release.py`, and the app still reads one if a release ever carries it. Because a published build normally has no manifest, same-version updates are again decided by the numeric release ID, so a republished 0.6.0 reaches an installed 0.6.0 instead of waiting for a version bump. The ZIP checksum is still verified against the sidecar before anything is unpacked. `v0.6.0` was cleaned to the same two files.
- New brand mark and a heavier wordmark, drawn once as vectors. The icon is now a white P cut out of the invoice itself, with a **teal sweep across the lower-left corner** and the check moved into a white ring so it reads as a stamp rather than a blob. Three masters replace the old two: the detail artwork from 40 px, a bolder 24–40 px version, and a 16–24 px version that **drops the check entirely** — at 16 px it was two grey pixels and a smudge. Colours moved to `#0B2447` navy, `#0E8C82` teal and `#12B3A6` for the badge, and the UI ink, accent buttons, headings and the 62 action glyphs now use the mark's own navy so the window and the icon are the same colour. The horizontal lockup sets “PayPamin” in **Inter Black** and “Flow” in **Inter Medium**, converted to outlines, and its viewBox is cropped to the artwork (`788.33:132`) instead of carrying 24 px of dead space above and below. Print PDFs are therefore 98 × 23.1 mm rather than 98 × 29.9 mm, still 90 mm of artwork plus 4 mm clear space.
- Fixed the real cause of dark fringes on soft icon edges: PyMuPDF already returns premultiplied samples, so multiplying by alpha a second time darkened every antialiased pixel. The badge also sat outside the rounded corner of the small master, which put navy-on-white fringe pixels exactly where the 32 px taskbar icon draws its silhouette. Both are corrected and both are now covered by the halo test.
- Sharpened the visual identity. The icon and the horizontal lockup now use **flat inks only** — the diagonal gradient and the gradient badge are gone, because at tray and taskbar sizes they read as a smear instead of a shape. The small-size master got a **thicker P and a smaller badge** so 16–24 px stays legible, and the "Flow" teal was deepened so white text on it and teal on the light background both keep contrast.
- The tray now receives a bitmap at the size the operating system actually draws instead of a 256 px icon the OS had to shrink: the simplified 32 px master on Windows (16/24/32 px tray) and the 48 px icon on macOS and Linux menu bars, with the large icon as a fallback.
- Removed the grey halo around every generated image. Both the product icons and the 62 UI action glyphs were downsampled from straight RGBA, which blends the colour of fully transparent pixels (black) into the edges; they are now reduced in **premultiplied alpha**, so edges stay the icon's own colour instead of fading through grey. Menu and button glyphs also use the brand navy (`#0F2F63`) instead of a washed-out grey, and the UI palette's titles, accent buttons, headings and canvas now share the same navy as the mark, with refreshed status-row tints and the same 739.88:180 proportions for the header lockup as the vector original.
- Reworked local logging into **exactly three files per day**. `app.log` holds technical events (including startup failures and updater steps), `activity.log` is a new dedicated file for the structured activity trail, and `errors.log` is the consolidated error view built from both. Startup and updater records no longer create separate `startup.log`/`update.log` files; an existing side log is merged into `app.log` on first start and removed. **Help → Show activity log** and **Help → Open log folder** open the new files, and every start writes one runtime banner with release, commit, Python and Tk versions.
- Yesterday's logs now move into `logs/arkiv/YYYY-MM-DD/` **and archived days older than seven days are deleted automatically**, including resolved-error snapshots. Only dated folders directly inside `arkiv/` and `arkiv/resolved/` are candidates, symlinks are skipped rather than followed, and today's three files are never touched.

The mark is now an invoice-style **P** with a teal check on deep blue, drawn as flat geometry without filters or transparency tricks so it stays sharp from 16 px to large print. A separate simplified master serves 16–32 px (tray, taskbar and Alt+Tab), where the detailed artwork turned to mush. Every PNG, ICO and ICNS file is now rasterised from the SVG masters by `assets/build_icons.py`, so artwork only changes in one place; the ICO carries 16–256 px and the ICNS 16–1024 px including Retina.

The release check now verifies that the PDFs stay vector-only at the documented size and that the package contains every print file.
